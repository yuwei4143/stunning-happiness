1 整體資料流

三份輸入，經規則引擎產出兩份結果。先看全貌，再逐步拆解。

輸入 → 處理 → 輸出

辨識產出支票辨識紀錄
會計匯出客戶主檔
會計匯出發票底稿
→
規則引擎標準化＋對照＋標記
→
產出待回填明細
產出名稱差異清單

「待回填明細」欄位順序與應付帳款明細表的支票區一致，覆核後可直接貼入 11505。

2 安裝與環境

只需 Python 3 與兩個套件；資料放 data/，產出寫 output/。

1

安裝相依套件

在專案根目錄執行，一次裝好讀取新舊 Excel 所需的套件：

pip install -r requirements.txt   # openpyxl → .xlsx；xlrd → .xls 客戶主檔
2

放好資料檔

把各期辨識批次與客戶主檔放進 data/。系統會自動略過 output/（已加入 .gitignore，不進版控）。

3 欄位如何被轉換

這是工具的核心。以下逐欄展示「辨識原始值 → 明細表格式」的轉換，每個都是固定規則、可重複、對黃金樣板 100% 相符。

3.1　支票帳號：銀行簡稱標準化 ＋ 帳號去符號

組合三個辨識欄位

銀行中國信託銀行
+
分行蘆洲
+
支存帳號303350005533
→
支票帳號中信蘆洲303350005533

銀行換簡稱（中國信託→中信），帳號去除破折號：150-031-0018158-7 → 15003100181587。

銀行簡稱對照（節錄）：中國信託→中信 · 第一銀行→一銀 · 合作金庫→合庫 · 彰化商銀→彰銀 · 臺灣中小企銀→台企 · 台中商銀→台中銀 · 三信→三信銀。農漁會分行另以對照表處理。

3.2　日期：民國格式統一轉西元

到期日 · 收票日 · 送票日

辨識（民國）115/07/08
→
明細表（日期）2026-07-08

民國字串、Excel datetime 一律正規化為日期，避免格式混雜。

3.3　用途與實收金額：依批次覆寫

用送票帳號判定整批用途，再決定實收是否填入

送票帳號15000100182967
→
用途託收
⇒
實收金額（留空）
送票帳號57100101404800
→
用途交換
⇒
實收金額填入票面

「交換」批填入票面金額；「託收」批尚未兌現，實收留空——這是你修正版的規則。

3.4　客戶簡稱與統編：對客戶主檔

以公司全稱／統編查主檔，補上明細表簡稱

辨識客戶裕煌成金屬有限公司
→
客戶簡稱裕煌成
統編97415975

查無對應者不臆測 → 轉為「名稱差異」標記（見第 6 節）。

小結：支票帳號、日期、用途、實收、送票、備註（禁背）、客戶簡稱／統編——全部由規則自動填妥。

4 執行：一鍵處理所有批次

最常用的流程。跟著四步走，從指令到看懂產出。

1

執行主程式

處理 data/ 內所有已設定批次，各自輸出一份待回填明細。

python3 src/run_all.py
2

讀懂終端摘要

每批顯示總筆數與需覆核筆數，末行回報名稱差異狀態。

批次處理完成：
  checks_20260618: 8 筆，6 筆需人工覆核 → output/checks_20260618_待回填.xlsx
  checks_20260624: 10 筆，4 筆需人工覆核 → output/checks_20260624_待回填.xlsx
  checks_20260708: 17 筆，9 筆需人工覆核 → output/checks_20260708_待回填.xlsx

無名稱差異，全部客戶皆已對應主檔。
3

開啟待回填明細

每列一張支票，欄位已是明細表格式；最後兩欄標出需覆核者與原因。

覆核後貼入明細表

處理標記為「是」的少數列（見第 5 節），確認無誤後把對應欄位貼進 11505 應付帳款明細表。其餘未標記者可直接採用。

其他用法

處理單一批次選用
python3 src/payable_filler.py data/checks_20260708.xlsx -o output/filled.xlsx

可加 --purpose 交換|託收、--send-bank、--send-account 覆寫批次設定。

5 四類人工覆核

工具不臆測。遇到判斷題一律在 需人工覆核／覆核原因 兩欄標記，交由你最後確認。以下每類都附實際範例。

辨識端

OCR 已標記

辨識專案本身標記需覆核者，帶入原因。

覆核原因：發票人印章無法辨識、客戶主檔未對應
合併票

同客戶多張票

同客戶同帳號多張票疑似併同一發票列，實收加總與到期取捨請人工決定。

覆核原因：同客戶多張票（5820890、5820891）疑似合併
金額

勾稽差額

票面與發票合計有差額（需比對發票列），附註待確認金額。

票面67,180 < 合計68,555　差1,375待確認
名稱差異

主檔查無客戶

辨識客戶在主檔查不到，以專屬註記並另行彙整。

【名稱差異】辨識客戶「泰閎鋼鐵有限公司」主檔查無

6 名稱差異建檔

名稱對不上主檔時（用字不同、主檔未登錄），工具單獨列出，讓你逐步累積別名、涵蓋率持續提升。這是一次性建檔、往後自動的循環。

1

查看差異清單

執行 run_all.py 後，開啟自動彙整的清單（去重，含出現批次與票號）。

📄 output/名稱差異待建檔.xlsx
辨識名稱簡稱統編出現批次支票號碼
泰閎鋼鐵有限公司待填待填checks_20260618XV0548947
2

確認正確的簡稱／統編

對照客戶主檔，決定該辨識名稱應對應的明細表簡稱與統一編號。

本例辨識為「泰閎鋼鐵」，主檔登錄為「泰閤鋼鐵」（用字不同）→ 簡稱 泰閤、統編 53057591。

3

填入別名對照檔

把一列加進 data/customer_alias.csv：

辨識名稱,簡稱,統編
泰閎鋼鐵有限公司,泰閤,53057591   # 辨識「閎」，主檔「閤」
4

下次自動解析

再次執行，該名稱自動對應、不再出現在差異清單。

無名稱差異，全部客戶皆已對應主檔。

7 驗證與維護

改完規則要能證明「產出仍符合你修正過的樣子」，並知道每種調整改哪裡。

黃金驗證

對修正版樣板逐欄比對100% PASS
python3 tests/verify_against_golden.py

用三個批次跑預填，與 11505_updated 逐欄比對。目前固定規則 197/197 相符；人工判斷欄位差異會另外列出，屬預期。

要調整什麼，改哪裡

調整項目檔案 → 位置
新增銀行簡稱src/normalize.py → BANK_SHORT
新增農漁會分行對照src/normalize.py → SPECIAL_BRANCH / SPECIAL_ACCOUNT
新增批次送票設定src/payable_filler.py → KNOWN_BATCHES
新增客戶名稱別名data/customer_alias.csv
更新客戶主檔覆蓋 data/customer_master.xls

專案結構

src/ normalize.py # 欄位標準化規則（銀行/帳號/日期/備註） customer_master.py # 客戶主檔對照 ＋ 名稱差異別名檔 payable_filler.py # 核心：辨識紀錄 → 待回填明細；批次設定 run_all.py # 一鍵處理所有批次 ＋ 名稱差異彙整 tests/ verify_against_golden.py # 對修正版樣板逐欄驗證 data/ customer_master.xls # 客戶主檔 customer_alias.csv # 名稱差異別名（逐步建檔） checks_*.xlsx # 各期辨識批次 output/ # 產出（不進版控）

維護鐵則：改完任何規則，務必重跑 verify_against_golden.py，確認固定規則維持 100% 相符再交付。

8 月資金計劃表 線上表單

把資料夾裡實際存在的 月資金計劃表.xlsx 變成瀏覽器表單：檢視、編輯、互動，每一格的變動即時寫回同一個原檔。

啟動

指定原檔路徑啟動（會直接寫回這個檔）
python3 src/fund_plan_server.py "C:/Users/berti/OneDrive/文件/Claude/Projects/月資金計劃表.xlsx" --open

Windows 可把 xlsx 拖到 啟動資金計劃表.bat；或把路徑寫進 fund_plan.config.json 後雙擊。巨大工作簿載入需 2–5 分鐘，看到「載入完成」再開 http://localhost:8765/。

畫面與互動

區塊內容
頂欄檔名／路徑、同步狀態（已同步／待寫回／寫入中／衝突）、立即寫回、重新載入、異動紀錄
月份分頁工作簿內所有 2026(N) 分頁，預設開當月；YYYYMMDD 版本分頁不列入
KPI支出合計、收入合計、月底目前現金、最低現金點、低於警戒線的天數
表格白底格直接輸入，Enter 往下、Tab 往右、Esc 還原；灰底 ƒ 欄（實際應付／應付餘額／目前現金）為公式、唯讀、即時重算；現金為負紅底、低於警戒線琥珀底
工具列關鍵字篩選、隱藏空白列、現金警戒線、新增一列（延伸表格並複製公式）、清空列（不刪列）

寫回原檔的安全機制

情境行為
每次編輯離開格子 1 秒內寫回原檔（同檔名、同路徑），並登錄到工作簿「異動紀錄」分頁（時間／分頁／列欄／原值／新值）
首次寫回先在原檔同層 備份/ 留一份 月資金計劃表_YYYYMMDD_HHMMSS.xlsx
原檔被 Excel 開啟寫不進去時變動留在記憶體、每 5 秒重試；關閉 Excel 即補寫
原檔被外部另存停止覆寫、亮紅色橫幅，由你選「放棄線上變動重新載入」或「以線上內容覆寫」
公式只顯示、不改寫；存檔時要求 Excel 開檔全量重算，正式數字以 Excel 為準

試用：python3 tests/make_fund_plan_sample.py 產生同構範例，再以 python3 src/fund_plan_server.py data/月資金計劃表_範例.xlsx --open 啟動；python3 -m unittest tests/test_fund_plan.py 跑 17 項測試。

綠 = 規則自動完成 琥珀 = 需人工覆核

產出的「待回填明細」欄位順序與明細表支票區一致，覆核完成後即可貼入 11505 應付帳款明細表。
