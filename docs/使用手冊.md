# 應付帳款自動預填工具 — 使用示範手冊

> 把支票辨識專案的產出，依你修正過的樣板規則自動整理成應付帳款明細表格式。
> **能由規則確定的自動填；需人工判斷的逐筆標記**，最後由你確認後貼入主檔。
> 固定規則欄位對黃金樣板 **100% 相符（197/197）**。

---

## 1. 這個工具做什麼

支票辨識產出的原始欄位，離「填進明細表」還差一層加工——銀行要換簡稱、帳號要去符號、
用途依批次覆寫、客戶要對主檔。本工具把可由規則確定的部分自動完成，需人工判斷的部分明確標記，
不靜默填錯。

```
辨識產出：支票辨識紀錄（每期批次） ┐
會計匯出：客戶資料明細表           ├─►  規則引擎  ─►  待回填明細.xlsx
會計匯出：發票底稿                 ┘   標準化           名稱差異待建檔.xlsx
                                      ＋主檔對照
                                      ＋覆核標記
```

---

## 2. 安裝與環境

需要 Python 3 與兩個套件（讀取新舊 Excel 格式）。在專案根目錄執行：

```bash
pip install -r requirements.txt   # openpyxl（.xlsx）、xlrd（.xls 客戶主檔）
```

- 資料檔放在 `data/`
- 產出寫到 `output/`（已列入 `.gitignore`，不進版控）

---

## 3. 三個常用指令

### 一鍵處理所有批次（最常用）

```bash
python3 src/run_all.py
```

處理 `data/` 內所有已設定的辨識批次，各自輸出一份待回填明細，並彙整一份名稱差異清單。
輸出示例：

```
批次處理完成：
  checks_20260618: 8 筆，6 筆需人工覆核 → output/checks_20260618_待回填.xlsx
  checks_20260624: 10 筆，4 筆需人工覆核 → output/checks_20260624_待回填.xlsx
  checks_20260708: 17 筆，9 筆需人工覆核 → output/checks_20260708_待回填.xlsx

無名稱差異，全部客戶皆已對應主檔。
```

### 處理單一批次

```bash
python3 src/payable_filler.py data/checks_20260708.xlsx -o output/filled.xlsx
```

可用參數覆寫批次設定：`--purpose 交換|託收`、`--send-bank`、`--send-account`。

### 對修正版樣板做黃金驗證

```bash
python3 tests/verify_against_golden.py
```

用三個批次跑預填，逐欄與你的修正版 `11505_updated` 比對，回報固定規則欄位相符率並列出每一處差異。
目前結果：**197/197（100%）PASS ✅**。

## 4. 自動完成的欄位規則

下列欄位由固定規則決定，對黃金樣板 100% 相符：

| 明細表欄位 | 規則 | 示例 |
|-----------|------|------|
| 支票帳號 | 銀行簡稱標準化 ＋ 支存帳號去符號 | `京城西港015009681`；`150-031-0018158-7 → 15003100181587` |
| 到期日／收票日／送票日 | 民國格式、datetime 一律轉為日期 | `115/07/08 → 2026-07-08` |
| 用途 | 依批次覆寫（送票帳號判斷交換／託收） | `15000100182967 → 託收`、`57100101404800 → 交換` |
| 實收金額 | 僅「交換」批填票面；「託收」批留空 | 託收 → 空白 |
| 送票銀行／送票帳號 | 依辨識紀錄，缺漏用批次設定補 | `永豐 · 15000100182967` |
| 備註 | 保留「禁背」 | 禁背 |
| 客戶簡稱／統編 | 由客戶主檔以統編、公司全稱對應 | `裕煌成金屬有限公司 → 裕煌成` |

**銀行簡稱對照（節錄）**：中國信託→中信、第一銀行→一銀、合作金庫→合庫、彰化商銀→彰銀、
臺灣中小企銀→台企、台中商銀→台中銀、三信→三信銀。新增機構請編輯 `src/normalize.py` 的 `BANK_SHORT`。

## 5. 需人工覆核的四類標記

工具不臆測，遇到判斷題一律在 `需人工覆核`／`覆核原因` 兩欄標記，交由你最後確認：

| 類別 | 說明 |
|------|------|
| **OCR 已標記** | 辨識專案本身標記需覆核者（印章不清、金額遮蓋等），帶入原覆核原因。 |
| **合併票** | 同客戶同帳號多張票疑似併同一發票列，實收加總與到期取捨請人工決定。 |
| **金額勾稽差額** | 票面與發票合計有差額（需比對發票列），附註待確認金額。 |
| **名稱差異** | 辨識客戶在主檔查無，以 `【名稱差異】` 專屬註記並另行彙整（見第 6 節）。 |

---

## 6. 名稱差異建檔流程

名稱對不上主檔時（用字不同、主檔未登錄），工具單獨處理，讓你能逐步累積別名、涵蓋率持續提升。

1. **執行後查看差異清單** — 跑 `run_all.py`，開啟 `output/名稱差異待建檔.xlsx`（含辨識名稱、出現批次、支票號碼）。
2. **確認正確的簡稱／統編** — 對照主檔決定該辨識名稱應對應的明細表簡稱與統一編號。
3. **填入別名對照檔** — 把一列加進 `data/customer_alias.csv`：

   ```csv
   辨識名稱,簡稱,統編
   泰閎鋼鐵有限公司,泰閤,53057591   # 辨識用字「閎」，主檔為「閤」
   ```

4. **下次自動解析** — 再次執行，該名稱自動對應、不再出現在差異清單。

## 7. 檔案結構

```
src/
  normalize.py              欄位標準化規則（銀行簡稱、帳號、日期、備註）
  customer_master.py        客戶主檔對照 ＋ 名稱差異別名檔
  payable_filler.py         核心：辨識紀錄 → 待回填明細；批次設定
  run_all.py                一鍵處理所有批次 ＋ 名稱差異彙整
tests/
  verify_against_golden.py  對修正版樣板逐欄驗證
data/
  customer_master.xls       客戶主檔
  customer_alias.csv        名稱差異別名（逐步建檔）
  checks_*.xlsx             各期辨識批次
output/                     產出的待回填明細（不進版控）
```

---

## 8. 日常維護

| 要調整什麼 | 改哪裡 |
|-----------|--------|
| 新增銀行簡稱 | `src/normalize.py` → `BANK_SHORT` |
| 新增農漁會分行對照 | `src/normalize.py` → `SPECIAL_BRANCH` / `SPECIAL_ACCOUNT` |
| 新增批次送票設定 | `src/payable_filler.py` → `KNOWN_BATCHES` |
| 新增客戶名稱別名 | `data/customer_alias.csv` |
| 更新客戶主檔 | 覆蓋 `data/customer_master.xls` |

> **改完規則務必重跑驗證**：`python3 tests/verify_against_golden.py` 應維持固定規則 100% 相符，
> 確保產出仍符合你修正過的樣子。

---

產出的「待回填明細」欄位順序與明細表支票區一致，覆核完成後即可貼入 11505 應付帳款明細表。
綠燈 = 規則自動完成；琥珀 = 需人工覆核。
